# 综合结论采用两段式：初步结论 → 完整结论

IP 风险评分是按需检测项（用户点击才执行，以保护第三方 API 配额），而它恰好是唯一能触发「高风险」的输入。若等用户点击后才给结论，首屏就没有定论；若只用自动项给结论，则该结论结构性地永远出不了「高」。我们决定分两段：自动项完成后立即给出**初步结论**并明确标注「未含 IP 风险评分」，用户触发按需项后重算为**完整结论**，覆盖度数字同步跳变。

## Consequences

- 初步结论的取值域被限制在「低 / 中」两档，这是设计意图而非缺陷；UI 不得让用户误以为初步的「低」等同于完整的「低」。
- 覆盖度数字从 3/9 跳到 4/9 这一可见变化，本身就是按需项最有效的转化诱因，优于任何促点文案。
- 与 [ADR-0004](./0004-verdict-must-state-coverage.md) 强耦合：两段式之所以可接受，前提是覆盖度始终可见。
