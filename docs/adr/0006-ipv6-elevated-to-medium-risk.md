# IPv6 泄露在 ipcheck Web 中升格为中风险信号（与 CLI 刻意分歧）

ipcheck CLI 把 IPv6 泄露排除在综合结论之外，只放进「检测建议」。我们决定在 ipcheck Web 中把它升格为**中风险**信号，直接参与综合结论判定。

## Considered Options

- **严格照搬 CLI** — 两端语义完全一致，用户不会困惑。否决理由见下。

## Consequences

- **这是一处刻意的语义分歧，不是移植疏漏。** CLI 排除 IPv6 的前提是它手里还有六个别的信号；ipcheck Web 的自动项只剩「系统时区一致性」一条，再排除 IPv6 就等于自愿把自动判定砍到只剩单一信号。
- 未来若有人拿 CLI 的 `has_bad` / `has_mid` 规则来"修正"Web 的判定逻辑，本 ADR 即为拒绝依据。
- 不升格为高风险：IPv6 泄露暴露的是地理位置，不像风险分 ≥70 那样直接关联封号。
