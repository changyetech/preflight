# 默认语言改为英语，五语种按路径分发，未译字段回落英文源

站点面向的是全球 AI 工具用户，中文只是其中一部分。我们把默认语言从中文改为英语：根路径 `/` 直接是英文（`/en` 保留为别名，canonical 指向 `/`），其余语种各占一个显式前缀 `/zh-hans`、`/zh-hant`、`/ru`、`/ar`。英文同时升为**源语言**——`Copy` 类型由 `src/locales/en.ts` 推导，其余语种按它对齐，漏译一个字段是编译错误。未译字段在 `getCopy` 里按**字段粒度**回落英文，因此补译可以一条一条来，不必凑齐一整份才能上线。

## Considered Options

- **保持中文为默认，英文继续挂 `/en`** — 否决：默认语言与目标受众不符，且"默认语言"与"源语言"分离会让后续写新文案时永远要先想"先写哪种语言"。
- **`/` 做 302 重定向到 `/en`** — 否决：多一跳、且根路径不再自带内容；显式别名页（`/en` canonical 指向 `/`）同样能兼容旧链接，代价更小。
- **按 `Accept-Language` 自动分发** — 否决：与规格第 7 节的既有立场冲突。本站用户大量在用代理，按地区/语言自动跳转正是他们最反感的行为，也会让"我看到的是哪个版本"变得不可预测。
- **未译语种整份回落英文（文件级）** — 否决：那样补译必须一次性交付一整份，实践中等于永远不补。字段级回落让译文可以增量落地。
- **用机器翻译先把五语填满** — 否决：本产品唯一的资产是可信度，而多数文案是解释性正文（"这意味着什么"），机翻的别扭措辞比诚实的英文回落更伤可信度。

## Consequences

- 语种清单的单一事实来源是 `src/copy.ts` 的 `LOCALES` 表；新增语种必须同时改三处：`LOCALES`、`src/locales/<id>.ts`、以及 `vite.config.ts` 的多页入口与对应的 `<id>/index.html`。三者不一致会被 `tests/i18n-routing.test.ts` 与 `tests/locales.test.ts` 抓到。
- 每个语种是一份独立静态资源，未注册路径（`/zh`、`/fr`）仍是**真实 404**，不做 SPA 回退——软 404 是既有红线（--content 修复轮 1 I1）。
- 阿拉伯语是唯一 RTL 语种，页面方向由 `LOCALES` 的 `dir` 字段驱动、写进对应入口的 `<html dir="rtl">`，**与译文进度无关**。CSS 中所有方向性属性必须用逻辑属性（`border-inline-start` / `text-align: start`），写 `left` / `right` 即视为违反本 ADR。
- 受 ADR 约束的文案（第三方披露、零留存声明、安装命令）在 `tests/copy.test.ts` 里对**每个语种**断言：漏译导致某语种丢掉 proxycheck.io / Turnstile 披露，是多语化引入的新失效方式，必须逐语种锁住。
- 与 [ADR-0008](./0008-privacy-informed-consent-upfront.md) 一致：语言仍完全由路径决定，不写 localStorage / cookie，不持久化任何语言偏好。
