# 能力边界导致的判级差异，在契约中命名并解释，不靠算法抹平

Web 结构性读不到 `$TZ`、读不到本机代理状态、读不到 Claude 端点配置，因此某些判级差异是能力边界造成的、算法上消灭不掉的。最典型的一例：用户把 `$TZ` 设成了与出口 IP 匹配的时区但系统时区没改，CLI 判低、Web 判中。我们决定把这类差异在 [docs/verdict.md](../verdict.md) §5 里逐条登记、命名并解释，而不是通过让两端算法趋同来消除它。

## Considered Options

- **让 Web 与 CLI 的结论强行一致**——CLI 也把「系统时区不一致」算作「中」。否决：这会对设了 `$TZ` 的用户产生误报，而设了 `$TZ` 的恰恰是最懂行的那批用户。用误报换表面一致，是拿正确性买整齐。
- **不登记，让两端各自演化**。否决：那么"两端共享判级契约"这句话就只是口号，而且半年后必定有人把它当 bug 来"修"。

## Consequences

- **同名不同物必须拆成不同的信号名**：原先笼统的「时区不一致」拆为 `tzMismatchCliEnv`（`$TZ` vs 出口 IP，仅 CLI）与 `tzMismatchSystem`（系统／浏览器时区 vs 出口 IP，两端可测）。前者贡献综合结论，后者只在 Web 侧贡献——在 CLI 侧展示但不贡献。
- 差异带**呈现约束**，不只是文档记录：Web 必须在时区项内说明"本项对应 Claude 桌面版，`$TZ` 网页测不到"；CLI 必须同时展示两条并标明只有 `$TZ` 那条进结论。缺了这些说明，差异就变成了用户眼中的 bug。
- **Web 的「低风险」在语义上弱于 CLI 的「低风险」**——它只意味着"在网页能测的范围内没发现异常"。这是覆盖度不可省略呈现的根本原因（[ADR-0004](./0004-verdict-must-state-coverage.md)），也是本 ADR 与它的连接点。
- 本 ADR 是未来所有"Web 测不到 X"问题的判例：新增此类差异时，登记到 verdict.md §5，而不是新开一次辩论。
