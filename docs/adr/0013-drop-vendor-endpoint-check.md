# 移除厂商端点检测（C5），ipcheck 只管网络环境

C5「Claude 端点检测」读本机的 `ANTHROPIC_BASE_URL` 与 `~/.claude/settings.json`，把端点分类为官方直连 / 国产大模型 / 第三方中转，并对命中 147 项冻结黑名单的中转站告警。它是 9 个检测项里**唯一读某个具体厂商专属配置**的一项。我们决定**移除它**：检测项 9 → 8，`C5` 这个编号作废且不再复用。

ipcheck 检测的是**网络环境**——出口 IP、DNS、代理、IPv6、时区、IP 风险。这些对任何联网程序都成立，与用户跑什么工具无关。端点配置属于另一个域：它是某个具体产品的设置，不是网络的属性。把它混在同一份报告里，让整个工具的适用范围被一家厂商框住。

## Considered Options

- **泛化为多厂商端点检测**（同时读 `ANTHROPIC_BASE_URL`、`OPENAI_BASE_URL`、Gemini 等）。否决：每家厂商的环境变量名、配置文件路径、官方 host 都不同且各自独立演进，这份清单只会持续腐烂——漏掉一家就是漏报，写错一个路径就是误报「官方直连」。而且"官方 host 白名单"本身要跟着厂商的基础设施变，我们没有任何机制能及时发现它变了。这是一个无底的维护面，换来的信息用户执行 `echo $ANTHROPIC_BASE_URL` 就能自己看到。
- **一个工具一张检测卡**（检出本机装了哪些 AI CLI，各占一项）。否决：**覆盖度分母会随本机装了几个工具浮动**，而契约 §4 与 [ADR-0004](./0004-verdict-must-state-coverage.md) 的整套论证建立在分母恒定上——用户看到「已完成 6」时必须能立刻判断缺了什么。更致命的是 Web 侧读不到本机，**连分母是多少都不知道**，「需 CLI N 项」里的 N 会变成未知数，覆盖度这个产品最核心的诚实性机制就此失效。
- **保留但只改文案措辞**（UI 上叫「AI 端点」，实现仍只读 Anthropic 的变量）。否决：展示为通用、实测只覆盖一家，是明知的误导。本项目对误导的容忍度就是零（[ADR-0004](./0004-verdict-must-state-coverage.md)）。

## Consequences

- **覆盖度分母恒为 8**：Web 侧 `X + Y + Z + W = 8`（`需 CLI` 从 5 降为 4），CLI 侧 `X + Z = 8`。
- **`C5` 是废弃编号，不得被任何新检测项复用**。ID 不复用的规则对已删除的 ID 同样成立——否则跨版本比对两份 `--json` 输出时，同一个 ID 会指向两件事。
- **删除 147 项黑名单**（`cli/src/probe/blacklist-147.txt`）与 `cli/src/probe/claude.rs`。名单是从已下线的二进制水印解出的冻结快照，本就无法刷新；C5 移除后它没有任何消费者。
- **[ADR-0010](./0010-verdict-contract-normative-cli-full-implementation.md) 的第 2 条刻意变更（黑名单从「高」降为分项提醒）随之作废**，契约 §2.1 中对应的那条也一并删除。ADR-0010 的其余部分（契约的权威性、CLI 全集 / Web 投影的关系、另外三条行为变更）继续有效。
- **代价（诚实记录）**：用户失去「我的端点是不是第三方中转」这个提示。这是真实的能力损失，不是零成本的清理。我们接受它——该信息用户自己一条命令就能确认，而维护一份跨厂商的准确清单我们做不到。
- 与 [ADR-0011](./0011-capability-boundary-divergence.md) §5.2 的关系：Web 的「低风险」弱于 CLI 的「低风险」这一点依然成立，理由收缩为 `tzMismatchCliEnv` 与 `tunOff` 两个仅 CLI 的中档信号。
