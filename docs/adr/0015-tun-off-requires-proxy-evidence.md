# `tunOff` 以代理迹象为前提，不再无条件贡献中风险

`tunOff`（C3）原定义是「TUN／VPN 未开启」即贡献中风险。这隐含了一个目标画像假设：用户**本来就该**开着代理。对不用代理的直连用户（美国本土用户是典型），「没开 TUN」是常态而非破绽——他们跑一次 CLI 就拿到一个永远无法消除的中风险，这是按画像写死的系统性误报。

信号的真实语义从来不是「TUN 没开」，而是「**在用代理，但不是 TUN 模式，所以存在 DNS／UDP／不认代理的进程这些泄露面**」。我们把前提补进定义：`tunOff` 命中 ⇔ **存在代理迹象** 且 TUN 明确未开启。

**代理迹象**取 C3 自己的两个观测，按三态（Kleene）取或：

- 环境变量代理已设（`HTTP_PROXY` 等，恒可判定）
- 系统代理开启（三态：开启／关闭／本平台未实现）

任一开启 ⇒ 迹象存在；无开启且系统代理**未实现** ⇒ 迹象未知（未知不冒充无迹象，契约 §2.3）；全部关闭 ⇒ 迹象不存在。迹象未知且 TUN 未开启 ⇒ `tunOff` 未知，不贡献；迹象不存在且 TUN 未开启 ⇒ `tunOff` 未命中——无代理时不存在「TUN 该开没开」这个问题。

## Considered Options

- **保持现状，靠自选择辩护**（装这个工具的人就是代理用户）— 否决：产品的判级不能依赖「不适用的人不会来跑」。误报就是误报，且这类用户拿到的中风险永远无法消除——契约 §4 说「检测失败」是用户唯一能自己解决的状态，一个解决不了的警告比失败更糟。
- **引入「受限国家清单」，仅当用户真实所在国受限时生效** — 否决：需要维护一份政治敏感、随时间漂移的国家清单；且「真实所在国」恰恰是本工具的测量对象，把它当判定输入是循环依赖。
- **把「C1 真实 IP ≠ O1 出口 IP」纳入第三个迹象** — 否决，三个理由：① CGNAT 按目的地分池时，两个探测会拿到不同公网 IP，凭空造出迹象（移动网络常见）；② 本 ADR 修的就是中国特化假设，把判定拴回 C1（中国大陆回显）等于把假设换个地方再写一遍；③ 网关级代理（软路由）用户的防护在网关，本机 TUN 开不开对他们不构成判据，靠 C1≠O1 把他们捞回来是把错的判据当对的用。
- **迹象未知时按「无迹象」处理（`tunOff` 判未命中而非未知）** — 否决：Linux／Windows 上系统代理探测未实现，「没探测」不是「没开」（C3 探测层已有的原则），塌缩会让呈现层把「确认无代理迹象」说成一个我们没有证据的结论。

## Consequences

- 判定表落在契约 [verdict.md §2.7](../verdict.md)；本 ADR 不重复它（判级规则只在契约修改）。
- 实现完全收在 CLI 的 `proxy::Status::tun_off()` 内——所需观测都在 `Status` 自身，探测层与信号接缝（`Report::signals()`）不变。Web 侧 `tunOff` 本就结构性不可测，无改动。
- `docs/verdict-cases.json` 的 `tunOff` 仍是派生布尔量：它是仅 CLI 的信号，golden 向量钉的是两端平价，对单端信号展开原始观测换不回任何东西；迹象门槛由 CLI 单测锁住（`cli/src/probe/proxy.rs`）。
- 行为变化：直连用户（无环境变量代理、系统代理关闭、TUN 关闭）从「中风险」变为「低风险」；Linux 等系统代理未实现的平台上，无环境变量代理时 `tunOff` 恒为未知、不再贡献结论。macOS 上 Clash 系统代理模式（系统代理开、TUN 关）的命中行为不变——那正是本信号要抓的场景。
- C3 卡片的色调跟随信号三态（已有逻辑）：直连用户的 C3 从警告色变为正常色，未知时保持暗色。
