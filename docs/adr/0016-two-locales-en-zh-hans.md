# 语种收缩为 en/zh-hans 两种，删除 /en 别名与回落机制

Supersedes [ADR-0009](./0009-english-default-five-locales.md)。

ADR-0009 规划的五语种运行一年后的实况是：en 与 zh-hans 已译全，zh-hant / ru / ar 三份 locale 文件全是空对象、整份回落英文，连各自入口 HTML 的 `<title>` 都还是英文（`ar/index.html` 挂着显式 TODO）。「路由与骨架已完备、译文永远是 2/5」不是过渡态，是稳态——我们决定把语种清单收缩到实际在维护的两种：英文（源语言，`/`）与简体中文（`/zh-hans`）。同时删除 `/en` 别名（英文只保留根路径一个入口），并删除为「多语种渐进补译」服务的字段级回落机制——两个语种都强制译全，漏键是编译错误。CLI 同步收缩（原为 en/zh-hans/zh-hant/ru 四种）。

## Considered Options

- **保留五语种骨架，继续等补译** — 否决：三个空语种每次改文案都产生"要不要顺手补"的决策税，hreflang/入口/测试全按 5 份维护，而收益为零。机翻填充在 ADR-0009 里已被否决过，理由（可信度）依然成立。
- **删语种但保留 `/en` 别名与回落机制，降低将来加回的成本** — 否决：`/en` 是英文的第二个入口，纯重复内容；回落机制在两语种都译全时是死重，且掩盖漏译（类型强制比运行时回落更硬）。将来真要加语种，是那次变更自己的事。
- **对被删路径做 301 到对应语种或根路径** — 否决：三个语种从未有过真实译文，不存在值得保全的外链资产；且真 404 与本站「未知路径不做软 404」红线同构，行为最诚实。

## Consequences

- `LOCALES` 收缩为两条，`dir` 字段随 ar 删除而移除；HTML 入口 6 → 2；hreflang 每页三条（`en`、`zh-Hans`、`x-default → /`）。
- `/en`、`/zh-hant`、`/ru`、`/ar` 与其余未注册路径一样是真实 404。
- **放开 ADR-0009 的逻辑属性强制**：「写 `left`/`right` 即违反 ADR」的前提是存在 RTL 语种，前提已不成立。逻辑属性降为建议（新代码可用可不用），已有的逻辑属性写法不回改。若将来重新引入 RTL 语种，须以新 ADR 恢复强制。
- Web 删 `PartialCopy` / `merge()` / 缓存，`zh-hans.ts` 与 `en.ts` 同为完整 `Copy`；CLI 删 `zh_hant.rs` / `ru.rs` / `is_fully_translated()`，`ArabicUnsupported` 并入统一的「不支持的语言」错误。
- **主题偏好持久化是「不写 localStorage」立场的显式例外**：2026-08 重设计引入三态主题切换器，偏好存 localStorage 键 `ipcheck-theme`（防闪白脚本首帧需读取）。它是纯外观偏好、无隐私载荷。**语言偏好继续不持久化**——语言完全由路径决定，与 ADR-0008 的隐私立场不冲突。
- 判级契约 §1.1 的标题跨端一致性约束收缩为「en/zh-hans 两语种下 O1–O6 逐字一致」，继续有效。
