# 分流泄露检测：新增 O5（DNS 出口泄露）与 O6（UDP 出口一致性）（父计划）

- 契约：[docs/verdict.md](../verdict.md) · [docs/verdict-cases.json](../verdict-cases.json)
- 决策：**ADR-0014**（本计划产出）· [ADR-0003](../adr/0003-ipv6-leak-via-third-party-dual-stack-echo.md) · [ADR-0004](../adr/0004-verdict-must-state-coverage.md) · [ADR-0008](../adr/0008-privacy-informed-consent-upfront.md) · [ADR-0011](../adr/0011-capability-boundary-divergence.md) · [ADR-0013](../adr/0013-drop-vendor-endpoint-check.md)
- 术语：[CONTEXT.md](../../CONTEXT.md)

## 目标

给两端各增加两个检测项，回答同一个问题：**用户的代理是不是真的全局接管了所有流量**。TCP/HTTP 走代理、UDP 与 DNS 却走直连，是 PAC／系统代理模式下最常见的两条漏，也是本产品用户最难自查的两条。

同时偿还一笔既有的债：契约把 C2 写成「本地 DNS 服务器**与 DNS 泄露**」，而 `cli/src/probe/dns.rs` 从头到尾只读本机 DNS **配置**，从未做过一次泄露探测。

## 核心决策（盘问结论）

| #   | 决策                                                                                   | 理由                                                                                                                            |
| --- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 统一叙事定为「**分流泄露**」，两项同源但**不合并为一项**                               | 合并后「DNS 成功 + UDP 失败」在覆盖度上无法诚实表达，而覆盖度是本产品唯一的诚实性机制（ADR-0004）                               |
| 2   | **C2 语义收缩**为「本地 DNS 服务器配置」，泄露判定拆到新项 O5                          | 真正的 DNS 泄露测试浏览器也能做，塞进「仅 CLI」的 C2 会击穿 `checks.ts` 里 `OnlineCheck` / `CliCheck` 的二分类型                |
| 3   | O6 语义定为「**UDP 出口一致性**」，不是「浏览器 WebRTC 泄露」                          | AI 命令行工具根本不发 WebRTC 流量；有意义的是它证明了 UDP 绕过代理                                                              |
| 4   | **分母 8 → 10**，新 ID 为 `O5` / `O6`（`C5` 仍是废弃编号，不复用）                     | 两项均为两端可测，属「可在线」类                                                                                                |
| 5   | CLI 侧 O6 用**手写 RFC 5389 STUN binding request**（裸 `UdpSocket`）                   | 保住 ADR-0010 的「CLI 是全集实现」，且不引 crate、不引 tokio                                                                    |
| 6   | 两个新信号**均为「中」档**                                                             | 契约 §3.2 的「高只出现在 `full` 形态」靠「唯一高档信号来自 O4」维持，任何不依赖 O4 的高档信号会当场打破它                       |
| 7   | O6 需 **≥2 个 STUN 报出同一 srflx IP** 且该 IP ≠ 出口 IP 才命中；两者不一致 ⇒ 无从比对 | ADR-0003 原则的第二次应用：用对照区分「未知」与「未命中」。多出口集群与对称 NAT 会自己暴露在这个对照里，不必用 `/24` 启发式去猜 |
| 8   | O5 判据为 **ECS 客户端子网的归属国 vs 出口 IP 归属国**                                 | 见下方「第 0 步实测结论」                                                                                                       |
| 9   | **浏览器禁用 WebRTC ⇒ O6 检测失败**，不是绿色「未泄露」                                | 与参考站 `refs/MyIP` 的刻意分歧：在「UDP 走没走代理」的语义下，禁用 WebRTC 只是把测量仪器关了                                   |
| 10  | 两项**首屏自动执行**，不做按需                                                         | 与 ipify 判例一致——按需的唯一理由是消耗本站共享配额，这两项都不消耗                                                             |
| 11  | **不引入脱敏／info-mask 机制**                                                         | O1 与 C1 已明文展示 IP，单给 O6 加模糊是两套标准；真要做是独立需求                                                              |

## 第 0 步实测结论（已完成，2026-08-12）

对 `https://<随机前缀>.edns.ip-api.com/json` 的实测：

```json
{
  "dns": { "ip": "172.253.198.221", "geo": "Japan - Google LLC" },
  "edns": { "ip": "212.50.249.0", "geo": "Japan - IT7 Networks Inc" }
}
```

三条结论，**其中第 2 条推翻了盘问中途的一版方案**：

1. **`edns` 段存在且稳定**——这是 resolver 转发查询时附带的 EDNS Client Subnet，即「resolver 眼里，客户端在哪」。
2. **不得用 `dns.geo`（resolver 归属国）作判据。** resolver 在哪个国家取决于**用户选了哪家 DNS 服务商**，与流量走没走代理无关：DNS 设 `223.5.5.5` 且 TUN 全局的用户，查询走了隧道到阿里、阿里从中国出去查权威，`dns.geo` = China ≠ 出口国 ⇒ **误报**。这个组合在本产品用户群里极常见。ECS 反映的是**客户端**，没有这个问题。
3. **不得比 ECS 的 IP 前缀，要比它的归属国。** ip-api 不告诉我们 ECS 掩码位数（Google／阿里用 /24，但不是所有 resolver 都是），比前缀是掩码敏感的；比国家则掩码多宽都不影响。
4. 旁证：`dns.ip` 两次调用返回不同地址（anycast 集群），`dns.geo` 稳定——「比 resolver IP 相等」确实不可行。

**Provider 选型收敛为单一的 `edns.ip-api.com`**：

- `ipleak.net` / `browserleaks.net` 的通配符子域实测**解析不出来**，两家排除
- `surfsharkdns.com` 可用且直接给 ISO2 `CountryCode`，但**不给 ECS**，只能支撑被否掉的第 2 条判据
- `https://ip-api.com/json/`（普通查询）返回 **403**，免费版不支持 HTTPS，「再查一次自己拿同源国家名」这条路不通

**由此引出一份新的共享数据**：ip-api 给英文国家名（`Japan`），`request.cf.country` 给 ISO2（`JP`），需要一张国家名 → ISO2 映射表。它与 ADR-0013 砍掉的「会腐烂的清单」不是同类——ISO 3166 英文短名是十年尺度稳定的标准，且一旦出错，错的是显示的国家名，不会把误判包装成安全结论。

## 全局验收标准

1. `make check-all` 全绿
2. `docs/verdict-cases.json` 扩充后的用例在**两端**全绿；故意翻转 O5 或 O6 的档位后**两端同时**变红
3. **平价验收**：同一网络环境下，CLI `--json` 与 Web 的 O5／O6 信号值一致；任何不一致必须能指回 `verdict.md` §5 中已登记的某一条差异
4. 覆盖度不变量：Web `X + Y + Z + W = 10`、CLI `X + Z = 10`，两端各有测试断言
5. `cli/src/domain/checks.rs` 里 `there_are_exactly_eight_checks_with_distinct_ids` **连测试名一起改**——留着旧名字是给未来的人埋雷
6. O5／O6 的标题在两端**共同支持的四个语种**下逐字一致（契约 §1.1）
7. 关掉 WebRTC（`about:config` 或隐私浏览器）后，O6 落「检测失败」而**不是**绿色
8. 使用 Cloudflare `1.1.1.1`（不发 ECS）时，O5 落「已完成 · 无信号」并给出明确说明，而**不是**「检测失败」，也**不是**「未泄露」

## 已知风险（诚实记录）

| 风险                                                | 说明                                                                                                                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`edns.ip-api.com` 的 HTTPS 是未定价的口子**       | `https://ip-api.com/json/` 返回 403（免费版不支持 HTTPS），而 `https://*.edns.ip-api.com/` 可用。这个不对称随时可能被收紧，届时 O5 在 Web 侧直接失效（CLI 可退 HTTP，浏览器不能——混合内容会被拦） |
| **单点依赖**                                        | O5 只有一个 provider，且第 0 步已证明没有可替代的。失败态是响亮的、可重试的，这是我们接受它的前提                                                                                                 |
| **不发 ECS 的用户拿不到 O5 结论**                   | Cloudflare DNS 用户是本产品的典型用户之一。这是真实的覆盖损失，由覆盖度诚实呈现                                                                                                                   |
| **O6 需要两个 STUN，Q7 的「少暴露一方」只守住一半** | `stun.cloudflare.com` 不新增观察者（本站已在 Cloudflare 上），但对照需要第二家。这笔账在 ADR-0014 里认                                                                                            |
