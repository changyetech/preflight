## 1. 范围与非目标

**改**：两端的呈现层（Web 全站视觉/排版/主题、CLI 人读报告）、语种架构（5 → 2）、随之失效的测试。

**不改**：

- 检测功能集不变——Web O1–O6 + C1–C4 展示、CLI 10 项全测，与现网一致，不新增检测项
- `docs/verdict.md` 判级契约与 `src/domain/`、`cli/src/domain/` 的判级逻辑**一行不动**
- CLI `--json` 的 schema **冻结**（平价验收 oracle）；「需关注」等新呈现信息不进 JSON，如需进入属于另一次契约变更
- `worker/` 的 API 行为不变（本就无语种逻辑）

## 3. 语种架构（细节见 ADR-0016）

- `LOCALES` 收缩为 en（`/`）+ zh-hans（`/zh-hans`），`dir` 字段随 ar 删除而移除
- HTML 入口 6 → 2：`index.html`（en）+ `zh-hans/index.html`；hreflang 声明 `en`、`zh-Hans`、`x-default → /` 三条；`vite.config.ts` 多页 input 同步收缩
- 语言仍完全由路径决定，不持久化语言偏好（ADR-0008 立场不变）
- CLI 语言解析顺序不变（`--lang` > 配置 `language` > 系统 locale > en），仅取值域收缩

## 4. Web 重设计

以原型为准，此处只记录**必须偏离或补充**的点：

1. **demo-only 元素不落地**：「示例数据 · 非真实检测」标记、演示时间线（`setTimeout` 假数据）、`recompute()` 里的演示判级逻辑、页脚「本页为设计稿」声明。真实数据流与状态机沿用 `src/usePanel.ts`，判级/覆盖度继续从 `src/domain/` 派生——原型 JS 只借鉴 DOM 结构与交互（菜单开合、主题应用、回顶）。
2. **语言切换器**：单键直切（决策 8），不用原型的五语种下拉。
3. **主题偏好持久化**：localStorage 键 `ipcheck-theme`，是 ADR-0008「不持久化」立场的显式例外（纯外观偏好，无隐私载荷），记入 ADR-0016。防闪白脚本需内联进**两个**入口 HTML 的 `<head>`。
4. **文案**：原型内嵌文案与现网 `src/locales/*.ts` 不完全一致处，**以现网文案为准**（文案近期刚过终审，如 C1「中国大陆」措辞、O2「无从比对」等）；原型新增的结构性文案（如 console 区标签、主题菜单项）补进两语种 Copy。
5. **覆盖度分段条**（10 格 meter）为新增呈现，格状态映射现有覆盖度模型：已完成/检测失败/进行中/按需未测/需 CLI，不变量 `X+Y+Z+W=10`（契约 §4）不动。
6. **C1–C4 由灰卡改为发丝线列表**（原型 `.cli-list`），对应删除 `CliCard` 的卡片形态。
7. 响应式、可达性（skip link、`aria-live` 结论播报、`aria-busy`、焦点环、reduced-motion）照原型落实。

## 5. CLI 重设计

以原型为准，补充与核对：

1. **新增文案键**（原型清单核对后）：`verdict.attention_label`、`verdict.attention_scope`、`values.risk_scale_note`、`values.reference_only`、各检测项标题行状态词 `checks.*.state`、O1 值行标签 `checks.o1.field_*`、C4 成因句与修复建议 `checks.c4.explain`/`fix`。两语种（en/zh-hans）同步补齐，键名以 `cli/src/copy/mod.rs` 现有结构为准适配。
   落地时按原型补齐的其余键：分组标题 `groups.*`（联网/本机、量词、全部完成、网页版做不到）、比对行两侧标签 `values.tz_system_label`/`tz_exit_label`、O4 值行标签 `values.network_type_label`/`detections_label`/`abuse_label`。`$TZ` 与 `IPv6` 是字面量（shell 变量名／协议名，两语种同形），同页脚的命令字面量一样留在渲染层，不进 Copy。
2. **「需关注」清单派生规则（不得写死）**：取全部 tone 为 warn/bad 的检测项，按严重度排序（bad 先于 warn，同级按检测项固定顺序）；`attention_scope` 句从信号数据派生——命中且**贡献综合结论**的信号所属项 vs 仅提醒项（契约 §2.1、§5.1）。检测卡顺序仍固定 O1→C4，不随严重度重排（编号是引用锚点）。
3. **风险分刻度**：分项色条与「26 起为中 · 76 起为高」对应契约 §6 分项分级（`<26` 绿 / `<76` 黄 / `≥76` 红）。**§6 的呈现义务照旧**：`anonymous: true` 且分数 51–75 时会「结论高 · 分项黄」，该项内必须保留解释文案。
4. **C4 修复建议**：仅当 `tzMismatchCliEnv` 命中且出口 IP 时区名已知时输出 `export TZ=<IANA 名>`；「无从比对」（契约 §2.4 第 3 步）不给建议。
5. **`=` / `≠` 比对符**替换现有 `→`；说明文字收 76 列悬挂缩进、降为 dim；`--verbose` 才出 description；`--no-color` 下全部语义仍成立（原型已验证）。
6. **页脚提示行**的 `config set` 命令写法以 CLI 实际子命令语法为准（配置键白名单 §8 不变）；`--verbose` 与 `--json` 各占一行。
7. **排版落地细则**（原型的 CSS 网格在终端里的等价物）：
   - **分组**：十项按「联网检测 O1–O6 / 本机检测 C1–C4」两段呈现，标题行用发丝线撑满整幅宽度，右端交代该组的量与性质（联网组报「全部完成」或失败数，本机组报「网页版做不到」）。检测项顺序仍固定 O1→C4。
   - **标签列**：卡内取值行的标签补齐到该卡最宽标签，取值落在同一列、折行悬挂在取值列；结论区 facts 与「需关注」共用另一条标签列。标签降 dim，不设跨卡固定列宽。
   - **列宽按终端列数算**：全角字符两列。折行断点是空格与全角字符边界（中文不用空格分词），并守标点禁则（句读不顶行首、开括号不落行尾）。
   - **「需关注」清单一项一行**（**偏离原型**：`.attn` 是 flex wrap 横排）。项数多时横排要靠 marker 辨认边界，一行扫过去认不清几项；一项一行则编号列直接对齐。
   - **宽度跟随窗口**：整幅宽度 = stdout 所在终端的列数，夹在 `[40, 110]`（原型是 `.screen{min-width:84ch;max-width:96ch}`，上限**放宽到 110**，让常见的 120 列窗口基本铺满；上限本身不取消——整幅宽度就是标题行到右端状态词的视线距离）；**说明文字另有 76 列上限**，窗口再宽也不摊开（`.note{max-width:76ch}`）。stdout 不是终端（重定向、管道、CI）时用固定 76 列——产物不该随当时的窗口大小变化。只在渲染前量一次，不监听 SIGWINCH（报告是一次性输出）。窄窗里排不下的成对元素一律「下一行右对齐」：标题行状态词、分组统计；C4 修复命令改为标签独占一行，命令本身绝不折断。
   - **标题行状态词右对齐**到整幅宽度的右端；失败卡无状态词。
   - **档位徽章**：彩色下反白色块，`--no-color` 下退回 `[ 中风险 ]`。
8. 契约呈现约束继续满足：CLI O1 标明归属数据来自 proxycheck（§5.4）、O2/C4 双条展示并标明谁进结论（§5.1）、失败项必须渲染（覆盖度数着它）。

## 6. 与既有规则的冲突登记

| 冲突 | 处理 |
|---|---|
| ADR-0009（五语种） | 被 ADR-0016 supersede |
| ADR-0009「写 `left`/`right` 即违反 ADR」 | 强制失去前提（无 RTL 语种），ADR-0016 放开；逻辑属性降为建议、已有的不回改 |
| ADR-0008 延伸的「不写 localStorage」 | 主题偏好为显式例外；语言偏好继续不持久化 |
| 契约 §1.1 标题跨端一致性 | 约束收缩为「en/zh-hans 两语种下 O1–O6 标题逐字一致」，继续有效 |
