## 1. 目标与非目标

**目标**：给出一张「已知可用的公共 DNS」清单，两端共吃同一份数据——CLI 用 `preflight dns` 展示并可选实测，Web 用独立页面 `/dns/` 展示。

**非目标（明确不做）**：

- **不改判级**：`docs/verdict.md` 的检测项注册表、信号域、判级规则**一行不动**。`preflight dns` 是工具型命令，不产出任何判级信号（§4.4）。
- **不改 API**：不新增 Worker 端点，`docs/api.md` 不动（§9 决策 3 的回撤结果）。
- **不做远端分发**：清单随版本内置，不联网拉取、不做本地缓存（§9 决策 2）。
- **不改体检主路径**：无子命令时的行为、`--json` 体检报告的 schema 均不变。
- **不做 DNSSEC / EDNS 能力检测**：与「我该配哪个 DNS」这个决策无关。

## 2. 数据契约：`docs/dns-servers.json`

两端共吃的**新增契约文件**，与 `docs/country-codes.json` 同一模式：Web 打进 bundle，CLI `include_str!` 编译进二进制。

### 2.1 结构

```json
{
  "servers": [
    { "ip": "1.1.1.1", "name": "Cloudflare", "region": "US", "domestic": false, "variant": "standard" },
    { "ip": "1.1.1.3", "name": "Cloudflare for Families", "region": "US", "domestic": false, "variant": "family" },
    { "ip": "223.5.5.5", "name": "AliDNS", "region": "CN", "domestic": true, "variant": "standard" }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ip` | string | IPv4 地址。**一条 IP 一个条目**，主备各占一行 |
| `name` | string | 服务商品牌名。**专名，两语种共用不翻译** |
| `region` | string | ISO2 国家码。渲染层按语种展开为「美国」/「United States」 |
| `domestic` | bool | 是否中国大陆运营。语义沿用 C2 现有的「可能暴露真实位置」 |
| `variant` | enum | `standard` / `security` / `family` / `adblock`，见 §2.2 |

**为什么一条 IP 一行而不按服务商聚合**：`--check` 要按实测延迟升序重排（§4.3），排序单位必须是被测对象本身；聚合成「Cloudflare: 1.1.1.1, 1.0.0.1」会让排序失去意义。

**为什么品牌名不翻译**：`AliDNS`、`Quad9` 是专名，中文用户同样以英文名认知它们；为 27 条各写两份译文是纯负担。地区与用途走 `region` / `variant` 两个可枚举字段，在渲染层双语化——这样两语种的增量成本是**常数**（4 个 variant 词 + 用到的国家名），而非与条目数成正比。

### 2.2 `variant` 取值

| 值 | 含义 |
|---|---|
| `standard` | 普通解析，不做内容过滤 |
| `security` | 拦截恶意/钓鱼域名 |
| `family` | 在 `security` 基础上再拦成人内容 |
| `adblock` | 拦截广告与追踪域名 |

**这一列是必需的，不是装饰**：`1.1.1.1` 与 `1.1.1.3` 平铺在一张表里而不加区分，会让用户随手挑一个然后困惑于「为什么有网站打不开」。

**落地时逐条核对**：每条的 `variant` 必须对照服务商官方文档确认（Quad9 默认拦恶意域名 → `security`；CleanBrowsing 各端点过滤级别不同），不得凭 IP 尾数猜测。

### 2.3 策展规则（准入标准）

清单**人工策展**，新增条目必须同时满足：

1. 有**公开的运营主体**（公司或非营利组织，可具名）；
2. 有**官方文档页**说明该 IP 的用途与过滤策略；
3. 有**公开的隐私政策**。

**明确排除**：来自公开扫描聚合源（如 public-dns.info 一类）的条目——那类数据收的是「扫描发现 53 端口开放的主机」，混有大量开放解析器与不明运营者，把它们标为「已知可用」推荐给用户是不负责任的。

### 2.4 已知缺口（记录在案，不在本次解决）

清单**没有持续存续验证机制**。策展只在新增时把关，一条服务商已停运的 IP 会一直留在表里。缓解手段是 `--check`——用户跑一次即可自行发现哪条不通，但这个发现不会回流到清单。修正它需要一条定时 CI（实测全表 + 失败开 issue），本次明确不做。

## 3. 与现有 `KNOWN_DNS` 的关系

`cli/src/probe/dns.rs` 现有私有常量 `KNOWN_DNS: [(&str, &str, bool); 27]`，标签为中英混排字符串（`"AliDNS 阿里 (CN)"`）。本次：

- 该常量**由 `docs/dns-servers.json` 取代**，升格为 `cli/src/domain/` 下的共享注册表，C2 探测与 `dns` 命令共同依赖；
- 中英混排标签随之收敛为 `name` / `region` 结构化字段——`--lang en` 下输出「阿里」是既有破绽，这次一并修掉。

这属于本次改动的**必要连带**（新命令与 C2 必须共用一份数据，否则同一台机器上两处对同一 IP 的称呼会不一致），不是顺手重构邻居代码。

## 4. CLI：`preflight dns`

### 4.1 命令形态

```
preflight dns [--check]
```

- **唯一 flag 是 `--check`**。不提供 `--refresh` / `--offline`——没有远端拉取，也就没有需要控制的联网行为（不带 `--check` 时该命令完全离线）。
- 全局 flag `--lang` / `--json` 对本命令生效。
- 不做二级子命令。整个 CLI 目前只有 `config` 一个旁支，为一个展示型功能开子命令树是过度结构化。

### 4.2 静态输出（不带 `--check`）

五列：**IP · 提供商 · 地区 · 国内标记 · 用途**。顺序为清单原序。

沿用 `render.rs` 既有的宽度自适应（`Style::sized`，commit `4a90e5d`），不为本命令造第二套排版。

### 4.3 实测输出（`--check`）

在同一张表**追加两列**：**延迟 · 状态**。

- **窄屏折叠**：宽度不足时把「地区」折进提供商列（渲染为 `Cloudflare (US)`），数据层仍是 §2.1 的结构化字段。不切换成独立视图。
- **按延迟升序重排**：跑 `--check` 的目的就是挑一个，最快的必须在第一行。不带 `--check` 时维持原序。

**判据（可达 + 延迟 + 弱正确性）**：向该 IP 的 UDP 53 发一个 A 记录查询，判定为「通」需同时满足：

1. 在超时内收到应答，且 **TXID 与请求匹配**；
2. `RCODE` 为 `NOERROR`，`ANCOUNT > 0`（非 `NXDOMAIN`）；
3. 返回的 A 记录**不是私网地址**。

任一不满足但有应答 → 状态标为「应答可疑」；无应答 → 「不通」。

**为什么不只测延迟**：被劫持或被投毒的 DNS 往往**响应最快**。只按延迟排序会把最坏的选项放在第一行，那比不做这个功能更糟。

### 4.4 不喂判级

`preflight dns --check` 的结果**不进** `docs/verdict.md` 的检测项注册表，**不贡献**任何信号，主路径体检的输出一个字节都不变。

理由：判级契约的价值在于「Web 与 CLI 同一判据」。Web 做不了实测（§5.2），让实测结果影响判级就会造成两端判据分裂——为一个 CLI 独有能力破这个口子，代价远大于收益。

**两端差异登记表**需补一笔：「CLI 有 `dns` 命令与 `--check` 实测，Web 只有静态清单页」——登记的是**能力差异**，不是判据差异。

### 4.5 协议实现：引入 `simple-dns`

**引包，不手写**。选型对比（2026-08-14 查证）：

| crate | 必需依赖 | 判断 |
|---|---|---|
| `simple-dns` 0.12 | 仅 `bitflags` | ✅ 采用 |
| `domain` 0.12 | `domain-macros`、`jiff`、`octseq`（tokio 可选） | 更重 |
| `hickory-proto` 0.26 | `data-encoding`、`idna`、`url`、`tracing`、`jni`、`rand` 等 10 个 | 过重 |

**为什么不沿用 `stun.rs` 的手写先例**：STUN 响应来自我们自己挑的、可信的服务器，格式是扁平 TLV，无指针。而 `--check` 解析的是**我们正在怀疑其被劫持的服务器**返回的敌意输入，且 DNS 的名称压缩指针（`0xC0`）正是手写解析器最经典的翻车点——指针成环会死循环，越界切片在 Rust 里是 panic，直接崩掉 CLI。既然判据里已承认对端可能有敌意，就不该给它一个自制解析器。多一个 `bitflags` 依赖，在一个已依赖 ureq + rustls 全家桶的 crate 里不值一提。

**硬约束（进验收）**：`cargo tree` 必须证明**未引入任何 async 运行时**（CLAUDE.md：不引 tokio）。依赖树会随版本漂移，这条是持续验收项。

### 4.6 `--json`

自成 schema，**不并入**体检报告信封：

```json
{ "servers": [ { "ip": "…", "name": "…", "region": "…", "domestic": false, "variant": "standard",
                 "check": { "reachable": true, "latency_ms": 12, "status": "ok" } } ] }
```

- `check` 字段**仅在 `--check` 时出现**，否则整个键不存在（而非 `null`）。
- `status` 取值：`ok` / `suspicious` / `unreachable`。
- 体检报告的 JSON 信封语义是「一次体检的结论」，DNS 清单不是结论，强行共用会污染那份 schema 的含义。体检 `--json` 的 schema 仍然冻结。

## 5. Web：独立页面 `/dns/`

### 5.1 形态与理由

**独立页面**，不是检测卡、不是落地页 section：

- **不做检测卡**：`Card.tsx` / `cards.tsx` 承载的语义是「我测了你，结论是 X」。DNS 清单是「这是可选项，你自己挑」，混进检测区会让用户以为系统在评判他们，也会污染检测项注册表。
- **不做落地页 section**：「公共 DNS 列表」是一个**独立的搜索意图**，与首页的「检测我的网络」不同。两个意图挤进一页，标题、H1、描述只能服务其中一个。

URL：`/dns/`（英文）与 `/zh-hans/dns/`（简体中文）。新增 2 个 HTML 入口，`vite.config.ts` 多页 input 同步扩充。

### 5.2 Web 不做实测

页面**只渲染静态表**。硬约束：**浏览器发不出 DNS 查询**——没有 UDP 53、没有原始 socket。唯一能做的是对支持 DoH 且开放 CORS 的少数端点发 HTTPS 请求，量到的是 HTTPS 往返而非本机 UDP 解析的实际体验。

一个只能覆盖两三家、且测的还不是真实路径的「可用性」，比没有更糟——它会给出误导性结论。页面改为明确引导：要测你这台机器上实际可用的，用 `preflight dns --check`。这也是把用户导向 CLI 的**诚实理由**，胜过硬塞一个安装 CTA。

### 5.3 路由与既有缺陷修复

- **语言切换器**：`src/copy.ts` 的 `LOCALES` 中每个语种是一条**固定 path**（`/` 与 `/zh-hans`），`LangSwitch` 直接链到 `other.path`。因此在 `/dns/` 点语言切换会被扔回 `/zh-hans` **首页**。本次将 `path` 改为**语种前缀**（`""` / `"/zh-hans"`），由切换器结合当前页 slug 拼出目标 URL，把「路径 = 语种前缀 + 页面 slug」这条规则显式化。这是 §5.1 带出的**既有缺陷**，必须连带修复。
- **尾斜杠**：`/dns` 需 301 到 `/dns/`。无尾斜杠是用户手输与外链的常见形态，让它 404 是自伤。优先使用 Static Assets 内建的 html_handling 行为，落地时验证；不满足再在 Worker 里补一条 301。
- **真 404 不变**：未知路径仍必须真 404，不做 SPA 回退（红线不动）。
- **sitemap 与 hreflang**：两个新 URL 均须加入。独立页面的全部意义就是被搜索命中（§5.1），不进 sitemap 与 hreflang 等于白做。

## 6. 文案

`variant` 与 `region` 的展开词进两语种 Copy（en 为源语言，zh-hans 完整译文，**无字段级回落**）。品牌名不进 Copy（专名）。

新增键（两端各自的 Copy 结构下同步）：4 个 variant 词、国内标记词、`--check` 的三个状态词、表头 5–7 列的列名、Web 页面的标题/描述/引导 CLI 的说明段。

## 7. 测试

- **共享数据**：`docs/dns-servers.json` 的 schema 校验（字段齐全、`variant` 在枚举内、`ip` 可解析、无重复 IP），两端各一份。
- **CLI**：静态表渲染（宽/窄/`--no-color`）、`--check` 的排序与折叠、`--json` 两种形态（有无 `check` 键）、DNS 应答解析的判据（NOERROR+A、NXDOMAIN、私网地址、TXID 不匹配、超时）以固定字节向量驱动，不打真实网络。
- **Web**：`tests/i18n-routing.test.ts` 扩充 `/dns/`、`/zh-hans/dns/` 命中与 `/dns` 的 301、未知子路径仍 404。

## 8. 验收

1. `docs/dns-servers.json` 为两端唯一数据源，`cli/src/probe/dns.rs` 的 `KNOWN_DNS` 常量与中英混排标签已消失。
2. `preflight dns` 与 `preflight dns --check` 在两语种 × 彩色/`--no-color` × 宽/窄终端下均无溢出、语义完整。
3. `--check` 结果按延迟升序；被劫持模拟（应答但私网地址）标为「应答可疑」而非「通」。
4. `cargo tree` 无 async 运行时。
5. `/dns/` 与 `/zh-hans/dns/` 可达，`/dns` 301，未知路径仍真 404；在 `/dns/` 切换语言落到**对应语种的同一页**。
6. `docs/verdict.md`、`docs/api.md`、体检 `--json` schema 均未改动。
7. `make check-all` 绿。
