# Preflight 判级契约

- 状态：**契约（normative）**——代码与本文不一致时，以本文为准（见 CLAUDE.md「Authoritative Source」）
- 适用范围：**两个实现**——Preflight Web（TypeScript，`src/domain/`）与 Preflight CLI（Rust，`cli/`）
- 相关：[ADR-0010](./adr/0010-verdict-contract-normative-cli-full-implementation.md)（本文的权威性来源）、[ADR-0011](./adr/0011-capability-boundary-divergence.md)（两端差异如何表达）、[ADR-0012](./adr/0012-cli-direct-third-party-not-worker-api.md)（CLI 不走本站 API）、[ADR-0013](./adr/0013-drop-vendor-endpoint-check.md)（移除厂商端点检测）、[ADR-0014](./adr/0014-split-tunnel-leak-checks.md)（新增分流泄露两项）、[ADR-0015](./adr/0015-tun-off-requires-proxy-evidence.md)（`tunOff` 以代理迹象为前提）

本文定义「一次网络环境体检得出什么结论」。它是**两个实现共同的判据**：CLI 是全集实现（10 项全测），Web 是它在浏览器 + 边缘能力边界内的**投影**（C1–C4 恒为「需 CLI」）。

判级规则**只在本文修改**。两端的代码、`docs/specs/` 下的设计规格、任何 UI 文案都不得单方面重述或改写它。

## 1. 检测项注册表

共 **10 项**，覆盖度的分母恒为 10。ID 是跨端稳定标识，**不得复用、不得改号**。

> **C5 是已废弃的编号**：它曾是「AI 厂商端点检测」，读本机的厂商专属配置。已按 [ADR-0013](./adr/0013-drop-vendor-endpoint-check.md) 移除——Preflight 只检测网络环境，不检测任何具体工具的配置。**C5 这个编号不得再被任何检测项使用**（ID 不复用的规则对已删除的 ID 同样成立）。

> **C2 的语义收缩过**：它原先写作「本地 DNS 服务器**与 DNS 泄露**」，但泄露判定从未实现——实现自始至终只读本机 DNS **配置**。按 [ADR-0014](./adr/0014-split-tunnel-leak-checks.md) 已把措辞收缩到实际能力（「本地 DNS 服务器配置」），泄露判定拆到新的 O5。**跨版本比对两份 `--json` 输出时需知道这一点**：同一个 `C2` 在旧版本的措辞里承诺过更多，但那份承诺没有对应的实现，不存在行为回退。

| ID | 语义 | 归属 | Web 执行 | CLI 执行 |
|---|---|---|---|---|
| O1 | 出口 IP 与归属（IP / 国家 / 地区 / 城市 / ASN / 组织 / IANA 时区） | 可在线 | 自动 | 自动 |
| O2 | 系统时区一致性（系统／浏览器时区 vs 出口 IP 时区） | 可在线 | 自动 | 自动 |
| O3 | IPv6 泄露 | 可在线 | 自动 | 自动 |
| O4 | IP 类型与风险（网络类型 / 代理检出 / 风险分 / 滥用收录） | 可在线 | **按需** | **自动** |
| O5 | DNS 出口泄露（DNS 查询是不是与出口 IP 从同一处出网） | 可在线 | 自动 | 自动 |
| O6 | UDP 出口一致性（UDP 流量的出口是不是与 TCP 观测到的出口 IP 一致） | 可在线 | 自动 | 自动 |
| C1 | 本机真实 IP（国内直连回显） | 仅 CLI | 需 CLI | 自动 |
| C2 | 本地 DNS 服务器配置 | 仅 CLI | 需 CLI | 自动 |
| C3 | 代理检测（环境变量 / 系统代理 / TUN） | 仅 CLI | 需 CLI | 自动 |
| C4 | `$TZ` 时区一致性（进程环境变量 vs 出口 IP 时区） | 仅 CLI | 需 CLI | 自动 |

**O5 与 O6 回答同一个问题**——用户的代理是不是真的接管了**所有**流量。TCP/HTTP 走代理、DNS 与 UDP 却走直连，是系统代理／PAC 模式下最常见的两条漏。两项同源但**不合并为一项**：合并后「DNS 测成了、UDP 没测成」在覆盖度上无法诚实表达，而覆盖度是本产品唯一的诚实性机制（[ADR-0004](./adr/0004-verdict-must-state-coverage.md)）。理由与被否决的方案见 [ADR-0014](./adr/0014-split-tunnel-leak-checks.md)。

**两项均为首屏／启动即自动执行，不做按需。** 按需的唯一理由是消耗本站共享的第三方配额（O4 的情形，ADR-0008），O5 与 O6 都不消耗。

**O4 的执行时机两端不同是刻意的**：Web 侧按需触发（用户显式同意把出口 IP 发给 proxycheck，ADR-0008），CLI 侧自动执行（用户装 CLI 并运行本身即为同意，且 CLI 用自己的配额，见 [ADR-0012](./adr/0012-cli-direct-third-party-not-worker-api.md)）。这不影响判级规则，只影响 `preliminary` 形态出现的频率。

### 1.1 检测项标题的跨端一致性

本文只规定 ID 与语义，**标题文案由各端自己的文案层维护**（Web：`src/locales/*.ts`；CLI：`cli/src/copy/`）。

**约束**：O1–O6 六项的标题，在 en/zh-hans **两语种**下必须**逐字一致**。改动任一端的这六个标题，必须同步另一端。用户在网页和终端看到同一个检测项，不能是两个名字。

（约束的边界是「两端都执行的检测项」，即全部 O 类。C1–C4 只有 CLI 执行，无从对齐。）

## 2. 信号域

「信号」是判级的输入，与检测项是多对一关系：一个检测项可以产出多个信号，也可以一个都不产出（纯信息项）。

| 信号 | 来源 | 定义 | 档位贡献 | Web | CLI |
|---|---|---|---|---|---|
| `riskScoreHigh` | O4 | proxycheck 风险分达到**当前匿名状态下的 deny 阈值**（详见 §3.1） | **高** | ✅ | ✅ |
| `tzMismatchCliEnv` | C4 | `$TZ` 时区 ≠ 出口 IP 时区 | **中** | — | ✅ |
| `tzMismatchSystem` | O2 | 系统／浏览器时区 ≠ 出口 IP 时区 | **中** | ✅ | **仅提醒** |
| `ipv6Leak` | O3 | IPv6 端点可达（详见 §2.2） | **中** | ✅ | ✅ |
| `abuseListed` | O4 | StopForumSpam 有滥用收录 | **中** | ✅ | ✅ |
| `dnsEgressLeak` | O5 | ECS 客户端子网归属国 ≠ 出口 IP 归属国（详见 §2.5） | **中** | ✅ | ✅ |
| `udpEgressMismatch` | O6 | ≥2 个 STUN 报出**同一** srflx IP 且该 IP ≠ 出口 IP（详见 §2.6） | **中** | ✅ | ✅ |
| `tunOff` | C3 | 存在代理迹象且 TUN／VPN 未开启（详见 §2.7） | **中** | — | ✅ |

**✅** = 该端可测且贡献综合结论；**仅提醒** = 该端可测、必须展示，但**不贡献**综合结论；**—** = 该端结构性不可测。

### 2.1 显式不贡献综合结论的观察

以下是明确的**分项提醒**，展示为黄色但**不拉高综合结论**。这是清单，不是遗漏：

- `networkType == "Hosting"`（机房 IP）——机房 IP 不等于有问题
- proxycheck 的 `proxy` / `vpn` / `tor` / `scraper` 检出
- 本地 DNS 为国内 DNS（C2）
- **出口 resolver 自身的归属国**（O5 的展示字段）——只展示，**不判定**，理由见 §2.5 第 3 条
- `tzMismatchSystem` **在 CLI 侧**（见 §5.1）

**C2 与 O5 的分工**：C2 是「**你配了什么**」（本机 DNS 配置里写的那个地址），O5 是「**查询真的从哪出去了**」。两者不互相蕴含——配了国内 DNS 但走全局隧道的用户，C2 提醒亮黄而 O5 不命中；配了境外 DNS 却在分流模式下从本地出网的用户，C2 不亮而 O5 命中。因此 C2 保持「只提醒不贡献」，判定由 O5 承担。

### 2.2 `ipv6Leak` 的判定

需要 IPv4 对照端点，否则无法区分「用户没有 IPv6」与「探测服务挂了」（ADR-0003）：

| v4 端点 | v6 端点 | 判定 |
|---|---|---|
| 通 | 通 | `ipv6Leak = true` |
| 通 | 不通 | `ipv6Leak = false` |
| 不通 | 不通 | O3 **检测失败**，不产出信号 |
| 不通 | 通 | 异常，按检测失败处理 |

IPv6 泄露贡献「中」而非「高」：它暴露的是地理位置，不像风险分 ≥ 70 那样直接关联封号。**这与 `ai-ipcheck` 的行为不同**（那边只进「检测建议」），是一处刻意修正，理由见 [ADR-0006](./adr/0006-ipv6-elevated-to-medium-risk.md) 与 [ADR-0010](./adr/0010-verdict-contract-normative-cli-full-implementation.md)。

### 2.3 「未知」不得冒充任何一侧

信号的取值不是布尔量，而是**三态**：命中 / 未命中 / 未知。**未知一律不贡献信号**——未知不是命中，也不该冒充未命中。

具体：

- `abuseListed` 为未知（StopForumSpam 不可用）→ 不贡献「中」。此时 O4 仍可为「已完成」：StopForumSpam 只贡献「中」，它挂掉不应连累 proxycheck 的结果。
- 时区无从比对（任一侧时区名缺失）→ 不算不一致。
- 任何检测项处于「检测失败」→ 其全部信号均为未知。
- **`riskScore` 与 `anonymous` 必须成对到达**：`riskScoreHigh` 的阈值由 `anonymous` 决定（§3.1），只拿到其中一个就无法判定。任一缺失 ⇒ O4 视为上游不可用，两者同时为未知。把缺失的 `anonymous` 默认成 `false` 会**静默抬高**阈值、造成漏报，而静默降级比响亮失败更难查。

### 2.4 时区比对算法（两端统一）

`tzMismatchCliEnv` 与 `tzMismatchSystem` 用**同一套算法**：

1. 归一化（去首尾空白、忽略大小写）后**比 IANA 名**，相同即一致
2. 名不同则比**当前 UTC 偏移**，相同即一致
3. 任一侧缺名、或名字解析不出偏移 ⇒ **无从比对**，按 §2.3 不贡献信号

**第 2 步不是宽容，是正确性。** `US/Pacific` 与 `America/Los_Angeles`、`Asia/Chongqing` 与 `Asia/Shanghai` 都是同一个时区的两个 IANA 名——只比名字会给设置完全正确的用户报中风险，那是一类系统性误报。风控端看到的本来也是偏移，同偏移不构成破绽。

> **本节原先是空缺**：契约只写了「时区不一致」，没规定怎么比。两端因此各自演化——Web 只比名字，CLI（沿用 `ai-ipcheck`）比名字再比偏移。同一组输入得出相反的信号值，而 golden 向量吃的是信号**结果**、覆盖不到这一层：契约的缺口不会被测试发现，只会被用户发现。现已统一，两端各有对应单测（`tests/timezone.test.ts` / `cli/src/probe/timezone.rs`）。

### 2.5 `dnsEgressLeak` 的判定

判据是**出口 resolver 眼里客户端在哪个国家**，与出口 IP 的归属国比。

**取值步骤（两端一致）**：

1. 解析一个**每次检测都重新生成的唯一子域**（唯一性是为了绕开各级 DNS 缓存——命中缓存拿到的是别人的观测值）。
2. 从响应中取 **ECS（EDNS Client Subnet，RFC 7871）客户端子网的归属国**，归一化为 **ISO 3166-1 alpha-2**（第三方返回英文国家名时，经 [docs/country-codes.json](./country-codes.json) 映射）。
3. 取 **O1 的出口 IP 归属国**，同样为 ISO2。
4. 两个 ISO2 逐字比较（大写后比），不同即 `dnsEgressLeak = true`。

**判定表**：

| ECS 客户端子网归属国 | 出口 IP 归属国 | 判定 | O5 的覆盖度归档 |
|---|---|---|---|
| 已知 `X` | 已知 `Y`，`X ≠ Y` | `dnsEgressLeak = true` | 已完成 |
| 已知 `X` | 已知 `X` | `dnsEgressLeak = false` | 已完成 |
| 响应中无 ECS 段 | 任意 | **无从比对**，不贡献信号 | **已完成** |
| 有 ECS，但国家名映射不出 ISO2 | 任意 | **无从比对**，不贡献信号 | **已完成** |
| 任意 | 未知（O1 未完成或未给出国家） | **无从比对**，不贡献信号 | 已完成 |
| 探测本身失败（网络错误、响应不可解析） | — | O5 **检测失败**，不产出信号 | 检测失败 |

**「无从比对」记「已完成」而不是「检测失败」**，因为探测确实成功了——我们拿到了回答，只是这个回答不含可判定的信息。把它记成失败会诱导用户反复刷新一个永远不会变的结果（§4：「检测失败」是用户唯一能自己解决的状态）。呈现层必须说明原因（如「你的 DNS 服务商不发送 ECS，本项无法判定」）。

**三条硬约束**：

1. **不得使用 resolver 自身的归属国作判据。** resolver 在哪个国家取决于用户**选了哪家 DNS 服务商**，与流量走没走代理无关：把 DNS 设成 `223.5.5.5` 且开着全局隧道的用户，查询经隧道到达阿里、阿里再从中国出去查权威——resolver 归属国 = 中国 ≠ 出口国，而这个用户**一点问题都没有**。这个组合在本产品的用户里极常见，用它判定就是系统性误报。resolver 归属**可以展示，不得判定**（§2.1）。ECS 反映的是**客户端**，没有这个问题。
2. **不得比 ECS 的 IP 前缀，只比它的归属国。** ECS 的掩码位数由 resolver 决定且响应里不一定给出（常见 /24，但不是所有 resolver 都是），比前缀是掩码敏感的；比国家不是。
3. **国家名映射不出 ISO2 ⇒ 未知，不得回退成「不同国家」。** 按 §2.3，未知不冒充任何一侧——把「我不认识这个国家名」当成「两国不同」会凭空造出误报。

### 2.6 `udpEgressMismatch` 的判定

判据是 **UDP 流量的出口是不是与出口 IP 一致**。需要**至少两个互相独立的 STUN 服务器**作对照，否则无法区分「UDP 真的绕过了代理」与「这个出口本来就是多地址集群」（这是 [ADR-0003](./adr/0003-ipv6-leak-via-third-party-dual-stack-echo.md) 那条「用对照区分未知与未命中」原则的第二次应用）。

**取值步骤（两端一致）**。先定义两个计数，判定表只依赖它们：

1. 向**两个及以上**独立的 STUN 服务器取**反射地址**（srflx，即服务器看到的客户端公网地址）。
   记 **`N_ok`** = **成功取回反射地址**的服务器数。无响应、超时、浏览器禁用 WebRTC 等一律**不计入** `N_ok`。
2. 在这 `N_ok` 个地址里**丢弃与出口 IP 不同协议族的**（见下方硬约束）。
   记 **`N_fam`** = 剩下的同族地址数（`N_fam ≤ N_ok`）。
3. 在这 `N_fam` 个地址里比对。

**判定表**。**按下表从上往下取第一条匹配的行**——各行的条件按 `N_ok` → `N_fam` → 取值分层，任何一组输入只会落进一行：

| # | 条件 | 判定 | O6 的覆盖度归档 |
|---|---|---|---|
| 1 | `N_ok < 2` | O6 **检测失败**，不产出信号 | 检测失败 |
| 2 | `N_ok ≥ 2` 且 `N_fam < 2` | **无从比对**，不贡献信号 | 已完成 |
| 3 | `N_fam ≥ 2` 且出口 IP 未知（O1 未完成） | **无从比对**，不贡献信号 | 已完成 |
| 4 | `N_fam ≥ 2`，同族地址彼此**不一致** | **无从比对**，不贡献信号 | 已完成 |
| 5 | `N_fam ≥ 2`，彼此**一致**，且 = 出口 IP | `udpEgressMismatch = false` | 已完成 |
| 6 | `N_fam ≥ 2`，彼此**一致**，且 ≠ 出口 IP | `udpEgressMismatch = true` | 已完成 |

**「检测失败」只由第 1 行产生**，即只看**有几个 STUN 真的答了**。协议族筛选**永远不会**造成检测失败，它只会把结果推进第 2 行的「无从比对」。这条分工是刻意的，因为两者的可恢复性相反：STUN 没答上来，刷新可能就好（§4 说这是用户唯一能自己解决的状态）；而「答了但都是另一个协议族」刷新一万次也一样，属于「测到了但不可比」。

> 本表**曾经按成因分类**（「因为被协议族筛掉」／「因为交换失败」），而成因可以并存——两个 STUN 里一个超时、另一个返回 IPv6 srflx 而出口是 IPv4，就同时满足两条，且两条给出相反的覆盖度归档。那是一处会让两端实现直接分叉的缺口。改按 `N_ok` / `N_fam` 两个计数分层后，上述输入落在第 1 行（`N_ok = 1`），唯一确定。

**「不一致」（第 4 行）是无从比对，不是未命中。** 多出口集群与对称 NAT 会自己落在这一行——它们本来就是最主要的误报源，用对照法让它们**自曝**，比用 `/24` 之类的启发式去猜它们要诚实。**第 4 行与第 5 行的综合结论必须相同**（都不贡献信号），差别只在呈现层的措辞与该项自己的颜色。

**浏览器禁用 WebRTC ⇒ 检测失败（第 1 行，`N_ok = 0`），不是绿色的「未泄露」。** 在「UDP 走没走代理」这个语义下，禁用 WebRTC 只是把测量仪器关掉了，不是测出了没问题。这与部分参考站的做法是**刻意的分歧**（[ADR-0014](./adr/0014-split-tunnel-leak-checks.md)）。

**协议族硬约束**：**反射地址是 IPv6 而出口 IP 是 IPv4（或反之）不得判命中。** 那正是 O3（IPv6 泄露）在管的事，在这里再算一次等于同一个事实进了两次判级。只比同协议族——这就是 `N_fam` 的全部作用，落进第 2 行时结论是「无从比对」而非任何一侧。

### 2.7 `tunOff` 的判定

`tunOff` 的语义**不是**「TUN 没开」，而是「**在用代理，但不是 TUN 模式**」——此时 DNS、UDP、不认代理的进程都在代理之外。没有代理的用户不存在「TUN 该开没开」这个问题：对他们无条件产出中风险，是把目标画像（用户本来就该开着代理）写进判级的系统性误报（[ADR-0015](./adr/0015-tun-off-requires-proxy-evidence.md)）。

因此命中需要**两个前提同时成立**：存在**代理迹象**，且 TUN 明确未开启。

**代理迹象**由 C3 自己的两个观测按三态取或（任一「开启」⇒ 存在；无「开启」且任一「未知」⇒ 未知；全部「关闭」⇒ 不存在）：

- 环境变量代理已设（恒可判定）
- 系统代理开启（三态：开启／关闭／**本平台未实现**——未实现是未知，不是关闭）

**判定表**：

| TUN 状态 | 代理迹象 | `tunOff` |
|---|---|---|
| 开启 | 任意 | 未命中 |
| 本平台未实现 | 任意 | **未知**，不贡献信号 |
| 未开启 | 存在 | **命中** |
| 未开启 | 未知 | **未知**，不贡献信号（§2.3：未知不冒充任何一侧） |
| 未开启 | 不存在 | 未命中 |

**迹象来源刻意不含「C1 真实 IP ≠ O1 出口 IP」**：CGNAT 按目的地分池会让两个探测拿到不同公网 IP、凭空造出迹象；且网关级代理（软路由）用户的防护在网关，本机 TUN 状态对他们不构成判据。理由全文见 ADR-0015。

## 3. 判级规则

### 3.1 三档

- **高**：任一高档信号命中
- **中**：无高档信号命中，且任一中档信号命中
- **低**：以上皆不命中

#### `riskScoreHigh` 的二维判定

阈值**不是一个数**，由 proxycheck 的 `detections.anonymous` 决定：

| `anonymous` | 判「高」的阈值 |
|---|---|
| `false` | 风险分 **≥ 76** |
| `true` | 风险分 **≥ 51** |

这两个数直接取自 **proxycheck v3 官方的 deny 边界**（分档建议表见 [docs/proxycheck.md §1.2](./proxycheck.md)，该文档带核实日期——第三方会改）。

**`anonymous` 不是「用户在用 VPN」**，而是 proxycheck 判定「这个 IP 当前正被用作匿名化地址」（TOR 出口、开放代理、住宅代理网络），并带延迟摘牌机制。实测：一个普通商业 VPN 出口是 `anonymous: false`；一个已知 TOR 出口是 `true`。

因此二维判定的实际效果是：

- **普通用户**（干净的 VPN／机房出口，`anonymous: false`）阈值从原先的 70 **升到 76**——更不容易被误报
- **真正在做匿名中转的 IP**（`anonymous: true`）阈值从 70 **降到 51**——VPN 的基准分是 50，这意味着「被判定为匿名地址、且有任何攻击历史」即为高风险

换句话说，这一维把「你在用 VPN」和「你的出口正在被别人拿来匿名作恶」区分开了。前者是本产品用户的常态，后者才是会触发 AI 服务风控的东西。

> **与 §2.1 的关系**：`proxy` / `vpn` / `tor` / `scraper` 这几个**布尔检出**按 §2.1 只是分项提醒，不拉高结论；`riskScoreHigh` 是独立信号，它可以。两者不矛盾——被判 VPN 是用户的常态，被判定为正在充当匿名地址且分数过线不是。
>
> **`ai-ipcheck` 用的是 v2，与 v3 不是同一把尺子**（实测对比见 [proxycheck.md §4](./proxycheck.md)）。阈值不能从 v2 时代的经验沿用——原先那个 70 就是这么来的。

### 3.2 三形态

结论有三种形态，**形态与档位是两个维度**：

| 形态 | 何时 | 取值域 |
|---|---|---|
| `insufficient` | **没有任何贡献信号产出结果**（相关检测项要么在进行中／已失败，要么已完成却**无从比对**——后者按 §2.3 同样不贡献信号） | **无档位** |
| `preliminary` | 风险分未知（O4 未触发 / 进行中 / 失败 / 配额耗尽） | 低 / 中 |
| `full` | 其余 | 低 / 中 / **高** |

**`insufficient` 不是可选的加分项。** 没有它，「首帧」与「全部检测失败」都会落到「低风险 · 未发现异常」——把没测成说成没问题，正是本项目最要防的那类误报。它与「低」的区别必须体现在**文案与配色两处**，只改文案不改配色等于没改（用户读色块快过读字）。类型层面必须让 `insufficient` **构造不出档位字段**，而不是靠约定。

**`preliminary` 必须带显式标注**（如「初步 · 未含 IP 风险评分」）。

**不变量：「高」只可能出现在 `full` 形态。** 这不是巧合，而是靠"唯一的高档信号 `riskScoreHigh` 来自 O4"维持的——风险分已知即为 `full`，未知即为 `preliminary`。**新增任何不依赖 O4 的高档信号，都会立即打破这个不变量**（一个确定的高风险会在 O4 失败时被压成「初步 · 中」），届时必须先修改本节，而不是绕过它。

> `dnsEgressLeak` 与 `udpEgressMismatch` **均为「中」档**，正是为了守住这条不变量：它们来自 O5／O6 而不是 O4，若给成「高」，一个确定的分流泄露会在 proxycheck 失败时被压成「初步 · 中」。守卫条件因此不变——**高档信号仍然只有 `riskScoreHigh` 一个**。

## 4. 覆盖度

**综合结论永远不得脱离覆盖度单独呈现**（ADR-0004）。

**Web**：`已完成 X · 需 CLI Y · 检测失败 Z`，另有 `按需未测 W`，仅在 `W > 0` 时呈现。
不变量：`X + Y + Z + W = 10`。其中 `Y` 恒为 **4**（C1–C4）——O5 与 O6 是可在线项，不进这一档。

**CLI**：`已完成 X · 检测失败 Z`。
不变量：`X + Z = 10`。CLI 没有「需 CLI」档（它就是 CLI），也没有「按需未测」档（O4 自动执行；O5／O6 同样自动执行）。

**分档规则**（两端一致）：

- 「检测失败」与「需 CLI」必须分开呈现：前者刷新可能就好，是用户唯一能自己解决的状态；后者是永久的
- 未触发的按需项**既不是**「已完成」，**也不是**「检测失败」（没发生过的事不叫失败），**更不是**「需 CLI」
- **配额耗尽计入「检测失败」**（两端一致）

## 5. 两端差异登记表

以下差异是**能力边界造成的、算法上消灭不掉的**。它们必须被命名和解释，而不是靠对齐算法假装抹平（[ADR-0011](./adr/0011-capability-boundary-divergence.md)）。任何"修复不一致"的改动必须先推翻本节。

### 5.1 时区：同名不同物

CLI 比的是 `$TZ`（命令行工具从进程环境继承的那个），Web 比的是系统／浏览器时区（对应图形界面应用）。Web **结构性读不到 `$TZ`**。

因此契约里是**两个信号**，不是一个：

- CLI：`tzMismatchCliEnv` 贡献「中」；`tzMismatchSystem` **展示但不贡献**（综合结论以命令行进程实际认的时区为准）
- Web：`tzMismatchCliEnv` 不可测；`tzMismatchSystem` 贡献「中」，作为 `$TZ` 不可得时的**降级代理**

**可观察后果**：用户在 shell 配置里把 `TZ` 导出成了与出口 IP 匹配的时区（正确），但系统时区没改 → **CLI 判低，Web 判中**。这是预期行为。

**呈现约束**：

- Web 必须在该项内显式说明「本项测的是系统时区（图形界面应用看到的那个）；命令行工具认 `$TZ`，网页测不到，属于 C4」。缺了这句话，CLI 用户会误以为自己的 `$TZ` 已被检查。
- CLI 必须**同时展示两条**（`$TZ` 一条、系统时区一条），并标明只有前者进综合结论。

**为什么不让 CLI 也把 `tzMismatchSystem` 算「中」**：那会对设了 `$TZ` 的用户产生误报——而设了 `$TZ` 的恰恰是最懂行的那批。用误报换表面一致，是拿正确性买整齐。

### 5.2 仅 CLI 的中档信号

`tzMismatchCliEnv` 与 `tunOff` 在 Web 侧结构性不可测。**Web 的「低风险」因此弱于 CLI 的「低风险」**——它只意味着"在网页能测的范围内没发现异常"。

**呈现约束**：Web 必须始终呈现覆盖度（`需 CLI 4`），使这个弱化对用户可见。这正是覆盖度不可省略的原因。

### 5.3 O4 的执行时机

见 §1。Web 按需、CLI 自动，导致 `preliminary` 形态在 Web 是常态（首屏）、在 CLI 是异常态（proxycheck 失败或配额耗尽）。

### 5.4 地理数据源不同，`tzMismatchSystem` 与 `dnsEgressLeak` 因此可能两端相反

Web 的 O1／O2 取 `request.cf`（Cloudflare 的地理库，免费无限）。CLI 没有这个东西，只能取 proxycheck v3 的 `location` 段。**两个地理库对同一个 IP 的判定可以不同**——国家、城市可能不同，**IANA 时区也可能不同**。

**§2.4 统一比对算法后，这处差异被大幅削弱**：两个地理库最常见的分歧是**同偏移的不同时区名**（`Asia/Shanghai` vs `Asia/Hong_Kong`、`Asia/Chongqing` vs `Asia/Shanghai`），而按 §2.4 的第 2 步，同偏移一律判一致——两端因此仍会得出相同的信号值。

**残留的可观察后果（时区）**：只有当两个地理库把同一个 IP 定位到**不同 UTC 偏移**的地区时（anycast 地址、新分配段、CDN 段最容易出现）两端才会分歧。此时 Web 与 CLI 的 `tzMismatchSystem` 可能一个判一致、一个判不一致。

**残留的可观察后果（国家，`dnsEgressLeak`）**：§2.5 比的是「ECS 客户端子网归属国」与「**出口 IP 归属国**」，而后者取自 O1——于是这一处数据源分歧**直接进入 O5 的判定**：

- ECS 那一侧**两端同源**（同一个第三方给出的客户端子网归属）
- 出口国那一侧**两端异源**（Web `request.cf.country`，CLI proxycheck v3 `location`）

**两个地理库把同一个出口 IP 判到不同国家时，两端会得出相反的 `dnsEgressLeak`**——一端「ECS 国 = 出口国」判不命中，另一端「ECS 国 ≠ 出口国」判命中。这与时区那处是同一个根因的两个出口，且**同样无法通过对齐算法消除**。它比时区那处更容易被看见：§2.4 的「同偏移即一致」把时区分歧吸收掉了大半，而国家代码没有这样的等价类——`HK` 与 `CN`、`US` 与 `CA` 之间不存在「同偏移」这种可以判等的中间量。

这不是任一端的缺陷，而是两个商业地理库的固有分歧，且**无法通过对齐算法消除**：Web 拿不到 proxycheck 的免费无限地理数据（它按次计配额），CLI 拿不到 `request.cf`（那是 Cloudflare 边缘运行时才有的东西）。

**呈现约束**：CLI 的 O1 必须标明归属数据来自 proxycheck。任一端都不得把自己的归属判定呈现为权威——用户拿两边结果对不上时，得能看出是数据源不同，而不是有一边算错了。**O5 必须把参与比对的两个国家都显示出来**（ECS 侧与出口侧各一个），否则两端 `dnsEgressLeak` 相反时，用户看到的是两个矛盾的结论而无从判断分歧出在哪一侧。

### 5.5 DNS 解析路径：浏览器 DoH vs 系统 resolver

**结构与 §5.1（`$TZ` vs 系统时区）完全相同**：两端测的是两个不同的东西，且都是各自那一侧唯一能测的东西。

CLI 走**系统 resolver**（命令行进程实际用的那条解析路径）。浏览器可能开着自己的 Secure DNS／DoH（Firefox 默认开启，Chrome 可配置），此时它的解析**根本不经系统 resolver**——O5 在 Web 侧量到的是浏览器那条路径。

**可观察后果**：同一台机器上两端可以得出**完全相反**的 `dnsEgressLeak`。典型情形是浏览器开着 DoH 到境外解析器（Web 判不命中），而系统 resolver 是运营商的、走直连出网（CLI 判命中）。

而**本产品的用户关心的恰恰是后者**——AI 命令行工具用的是系统解析路径，不是浏览器的。**Web 的 O5 因此是降级代理**，与 `tzMismatchSystem` 之于 `tzMismatchCliEnv` 是同一种关系。

**呈现约束**：Web 必须在该项内显式说明「本项测的是**浏览器**实际使用的 DNS 路径；如果你开了浏览器的 Secure DNS／DoH，它与命令行工具走的系统 DNS 不是同一条路，以 CLI 的结果为准」。缺了这句话，用户会拿一个绿色的网页结论去为命令行工具背书。

### 5.6 WebRTC 栈 vs 裸 UDP socket

Web 经**浏览器的 WebRTC 栈**取反射地址，CLI 直接发 **RFC 5389 binding request**（裸 UDP socket）。

浏览器侧的取值可能被扩展、企业策略或隐私设置整体禁掉，此时按 §2.6 落 **O6 检测失败**；CLI 的 UDP 直接走系统路由，不受这些限制。

**可观察后果**：同一台机器上 **Web 报 O6 检测失败、CLI 正常出结论**。这不是任一端的缺陷——浏览器有权拒绝暴露本机的 UDP 候选，那是它的隐私模型。

**呈现约束**：Web 的 O6 失败态必须区分「探测超时」与「浏览器不允许」两种原因。前者刷新可能就好，后者刷新一万次也一样，只能改浏览器设置或改用 CLI。

## 6. 分项分级（不等于综合结论）

风险分的**分项**颜色：`< 26` 绿 / `< 76` 黄 / `>= 76` 红。

三个分界直接对齐 proxycheck v3 自己的分档（0–25 / 26–50 / 51–75 / 76–100，见 [proxycheck.md §1.2](./proxycheck.md)）：把它的四档收成三色时，中间两档合并为黄——**绿=它建议放行的区间，红=它对任何 IP 都建议拒绝的区间**。

这与 §3.1 的综合结论仍是两件事，实现上**不得复用同一个函数或常量**：

- 综合结论是**二维**的（51 或 76），分项分级只看分数
- 两者在 `anonymous: false` 时同界（都是 76），在 `anonymous: true` 时**不同界**——结论从 51 起判高，而分项要到 76 才转红

**`anonymous: true` 且分数落在 51–75 时会出现「结论高 · 分项黄」。** 呈现层必须在该项内说明这个 IP 正被用作匿名化地址、判高的阈值对它降到 51——否则用户看到高风险结论却找不到哪一项显红，会以为结论算错了。颜色是快读信号，文字是解释，这一档缺了文字就说不通。

（原先的 34 / 70 是单维时代的产物：70 继承自 `ai-ipcheck` 的 v2 经验，34 则由 Hosting 的基准分推得。两者都不再适用。）

## 7. 一致性保障机制

### 7.1 共享 golden 向量

`docs/verdict-cases.json` 是本文 §2–§3 的**可执行形式**。每条用例声明：输入信号集合、期望形态与档位、适用侧（`web` / `cli`；两端通用的用例两项都写）。

**两端都必须**以参数化测试消费它：Web 侧 vitest，CLI 侧 `cargo test`。

该文件同时出现在两条 CI workflow 的 paths 过滤中——改契约必然触发两端验证。

### 7.2 修改流程

判级规则的任何变更，顺序恒为：**本文 → `verdict-cases.json` → 两端实现**。反向（先改实现再补文档）是本文明确禁止的。

## 8. CLI 配置红线

CLI 有配置文件（`~/.config/preflight/config.toml`），**允许的键是白名单**：

| 键 | 说明 |
|---|---|
| `language` | 界面语言 |
| `proxycheck_key` | proxycheck 免费 key（可选，把配额从 100/天 提到 1000/天） |
| `timeout` | 网络探测超时 |
| `no_color` | 关闭彩色输出 |

**禁止**：任何判级阈值、任何检测项开关。

理由：用户能配阈值，本文就作废了——"我的 CLI 说低风险"从此不再是一句有意义的话，golden 向量也不再能证明任何事。

**未知键必须报错退出，不得静默忽略。** 静默忽略会让拼错的键表现成"配了但没生效"，这是最难查的一类问题。

## 9. 隐私约束

- 两端都**不持久化任何检测结果**（ADR-0008）。
- proxycheck key 绝不出现在：`--json` 输出、终端渲染、错误信息、panic backtrace、日志。CLI 写入配置文件时权限置为 `600`。
- CLI **不得**接受"查询任意 IP"的参数。查询目标恒为本机探测到的出口 IP——否则 CLI 退化成一个任意 IP 查询代理，与 Web 侧同一条硬约束（`docs/api.md` §3）同源。
